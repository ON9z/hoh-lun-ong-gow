# 机制要能自证：拿已知坏样本喂一遍，证明它真的会红

判据：我拿**已知会失败的样本**喂过这个检查吗？它真的红了吗？**贴出那次运行的输出。**

**⇒ 为什么**：一个**从未红过**的检查，与没有检查不可区分 —— 而它更坏，因为它**买走了注意力**。

**实例**：一个守卫的断言「所有已分类项都必须被扫描器命中」，
**它的清单是从扫描器当前输出里量出来的** ⇒ 测试**必然通过**，
且扫描器明天少命中一项时测试会红，而人会去改那个数字，**而不是去看判据为何退化**。
**⇒ 把测试拟合到代码，是「自证」的反面。**

**⇒ 做法**：
① 喂靶用的「坏版本」**必须从历史版本取到临时路径**（见准则 03），**不得原地改文件**；
② 让清单来自**独立依据**，并让断言**闭合**（命中 ∪ 已知例外 == 全集），
   使「判据退化 / 变强 / 恒空」三种都会红；
③ 守卫的**输出要与权威源对账**。

**⚠️ 补一条（本条的**更前置**形态）：验器自己崩掉 ⇒ 那是「未验证」，**不是「通过」**。**

**实测**：我写脚本核对一个计数声明，脚本**因为语法错根本没运行**（没有任何输出）；
而我**没有注意到缺了输出**，就把那个声明提交了。**⇒ 声明进了公开产物，它从未被核对过。**

**⇒ 判据**：**任何"声明 + 验器"的组合，验器没产出 == 声明未验。**
**缺输出、报错、退出码非零 —— 三种都必须让声明停下来**，而不是让流程继续。
**⚠ 最危险的是"没输出"** —— 它看起来像"跑完了，没问题"。

**⇒ 自检**：跑完验器之后，问一句
**「它的输出在哪？我看到的这段，是它写的，还是我以为它会写的？」**

**⚠️ 再往前一步：被 `if` 包住的前置条件不成立时，**连"没输出"都没有**。**

**实测（同一形状的第三次）**：
```python
if tool.exists() and anchors_present:      # ← 没有 else
    try:   ...run the check...
    except Exception as e: print("[!!] 没能跑"); bad += 1
```
**⇒ 工具被删/改名 ⇒ 整个 `if` 体跳过 ⇒ 什么都不打印、计入 0 ⇒ 上层报"全部通过"。**
而且**那段注释写的是**「工具不在/坏了 ⇒ 报出来，**不静默当通过**」——
**注释在描述一个代码没有的行为。**

**⇒ 判据**：**守卫的入口条件不成立，与守卫失败是同一件事 —— 都必须红。**
```python
if not precondition:  report_red(); bad += 1
else:                 try: … except: report_red(); bad += 1
```

**⚠️ 同族（都已实测）**：
- `if X is not None:` 包住的健康检查 ⇒ **被守护对象不存在时，检查永不介入 = 零自愈**；
- 上一版守卫的 `if not path.exists(): return {}` ⇒ **文件不在时静默返回"没问题"**；
- 这一处。

**⇒ 它们的共同点**：**把"没检查"写成了"检查通过"** —— 而两者的输出**长得一模一样**。
