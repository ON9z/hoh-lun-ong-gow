# 未核就写未核：不许把「判不了」写成结论

判据：这一句是**实测**、**转述**，还是**推断**？我把它标出来了吗？以及：**这个数（这句话）我拿什么对过？**

**实例**：面对静态读码定不了的问题，最容易的失效是 —— **判不了 ⇒ 于是给一个听起来确定的结论**。
**措辞强度必须 = 证据强度。**

**⇒ 做法**：**提前声明上限**（比一个猜的答案有用得多）：
> 「若轨迹没落盘，我会明说**需要一次真跑的 trace 才能定**，而不是给你一个猜的答案。」

**⚠️ 配套发现**：观测字段**不落盘** = 该问题**在静态层面不可判** ⇒ 要先说这句，再给候选。

**同族**：报「N 次 / 每 X 分钟 / 全部 / 普遍」时，这些数**从哪来**？
乘法推的 ⇒ 禁止；单次测量 ⇒ 需多样本；样本 < 全体的 10% ⇒ 只能说「已测的 N 个」。

**⚠️ 最有用的那一半：出口闸比"判据更准"更能降低错误率。**

**实测（2026-09-21，两侧都装了这道闸之后）**：
一天内"坏判据"的次数**没有下降**（正则漏 `re.M`、f-string 反斜杠、`grep` 用词与原文不符、跨语言搬判据……两侧合计十余次）。
**但最终报出去的假信号大幅下降** —— 因为**出口那道闸**从
「**量到一个数就报**」换成了「**报之前先拿第二个方法对一眼**」。

**⇒ 判据**：
> **「这个数我拿什么对过？」—— 答不出来的，不算数。**
> （与「答不出**什么时候该想起它**的，不算行为准则」是同一把尺子，量的是两样东西。）

**⚠️ 为什么这条重要**：**"把判据造得更准"是能力问题，缓慢且不可靠；
"出口加一道闸"是流程问题，装上就立刻见效 —— 而它不要求判据先变好。**
**⇒ 别等判据变准，先装闸。**
