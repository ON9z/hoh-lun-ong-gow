# 半个修复比没有修复更误导

判据：改一条判据 / 加一个过滤器之前，问「**这条逻辑作用在几个地方？我改了几个？**」
只改一处 ⇒ 你很可能把**看得见的噪声**换成了**看不见的污染**。

**⇒ 为什么**：一条判据通常有**两层以上的作用点**：
「**命中什么**」是一层，「**用什么去命中 / 怎么传播**」是另一层。
只修前者，噪声**并没有消失**，只是**换了形态** ——
而新形态往往**看起来更像结论**，因为它已经过了一道过滤。

⇒ 真正危险的地方：**你是在用"我减少了几千条误报"这个成果，换来"我不能再一眼看出它是错的"这个损失。**

**实例**：一个静态普查工具靠**名字**判断"某个函数体内会不会发网络调用"，并靠**一个排除集**
压掉内建方法名的误报。第一版只把排除集用在「**命中**」那一层，
**没有**用在同一逻辑的「**传播**」那一层（"谁调用了会发网络的函数"）——
于是字典取值的 `get` 把误报**传播**给了**每一个调过 `.get()` 的函数**：

| | 命中数 | 观感 |
|---|---|---|
| 只改之前 | 2776 | 绝大多数是字典取值 ⇒ **一眼看得出是噪声**，没人会当真 |
| 只改一处之后 | 152 条「高特异性候选」 | **其中大半仍然是假的** ⇒ 而**小名单正是人会逐条读的那一份** |

⇒ **修完比修之前更危险** —— 因为它现在是**一份被信任的名单**。

**⇒ 做法**：

① 动手前先把这条判据的**作用点列全**（常见的有：**命中** / **传播** / **去重** / **排序** / **截断**，
   各自一层）。逐层问「**这一层也该排除吗？**」
② **排除必须打印出来**（被排除的**名字**+**条数**）——
   否则「提高精度」会退化成「**静默地少看**」。白名单沉默 = 你不知道自己没看什么。
③ 改完**立刻拿同一份输入再看一次**：命中数掉了多少？**掉下去的那些，是被排除了，还是被藏起来了？**

**⚠️ 与准则 13 的分界**：13 讲「守卫只进不出 ⇒ 对象**累积**」；
本条讲「**一条判据有多个作用点，你只改了一个**」——
前者是越积越多，后者是**你打算看的那份名单，被换成了一个更值得信任的形态**。

**⚠️ 与准则 05 的分界**：05 讲「断言要双向夹逼」；本条讲「**修复的作用点要全覆盖**」——
你可以每条断言都双向验过，却**只在其中一层加了过滤**。
