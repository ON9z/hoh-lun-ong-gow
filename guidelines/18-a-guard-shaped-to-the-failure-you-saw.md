# 照你**看见过的那一次失败**造的守卫，只在那个方向上有效

判据：写下任何「**如果出现 X 就采取 Y**」的守卫 / 熔断 / 冷却 / 降级时，问：
**「X 是我【见过】的那一种，还是我【定义】的那一类？」**
答不出 ⇒ 你造出的是一条**单向守卫** —— 它挡住了你踩过的那一脚，
而对**同一件事的另一半失明** —— 且**它每一秒都看起来在工作**。

**⇒ 为什么**：失败第一次出现时，你手上只有**一个样本**。
从样本里提取出来的条件会**不自觉地贴着那一个样本的形状** ——
包括它的**措辞**、**异常类型**、**触发路径**。而那都是「**那一次**」的特征，不是「那一类」。

**实例（实测，2026-09-23）**：一个行情抓取器带「封禁冷却」：命中就把冷却置到 120 秒后、停止取数。

```python
except Exception as e:
    if "Remote end closed" in str(e) or "RemoteDisconnected" in str(e):
        self._cooldown_until = time.time() + 120 ; break     # ← 只有这两个字符串才冷却
    if attempt < 2:
        time.sleep(1 + attempt)                              # ← 退避
```

- 这条守卫**是照着观测到的那一次**（连接被对端关闭）造的 ✔ 对那个形状**完全有效**
- 但**超时**走进同一段 `except`，**不匹配**那两个字符串 ⇒ **不置冷却、照常重试**
  ⇒ 每次重试各自 `sleep` ⇒ 单次调用最坏 **3×超时 + 3 秒阻塞睡眠**
- 而调用点是**按标的逐个**来的（单轮 **200+** 个）⇒ 最坏 **~60 分钟**
- ⇒ **而冷却始终没有生效过** —— 它在等一个**永远不会出现的字符串**

⚠ 代价是隐藏的，因为它表现为「**守卫已实现**」：代码里有冷却、日志里没报错、
看代码的人在那一行看到一个看起来完备的防御。

**⇒ 做法**：

① 写条件之前，先问「**这一类失败有几种形状？**」把**见过的**和**没见过的**分开列出来。
② 拿不准就按「**除成功以外都算**」写（默认拒绝），**不要**按「我见过的那种」写。
③ 给守卫补一个**另一侧的喂靶**（准则 10）：**喂它一种你没见过的失败**，看它会不会沉默。
   只喂「你见过的那一种」，证明的是**夹具**，不是守卫。
④ **有状态**的守卫（冷却 / 熔断 / 退避预算）尤其危险：它一旦不置位，
   **每一次调用都重新付全额代价** —— 而"没置位"这件事本身**不会报错**。

**⚠️ 与准则 05 的分界**：05 讲「**测试断言**必须双向夹逼」（我写的断言在放松方向也要变红）；
本条讲「**生产里的防御性守卫**是照观测到的那个样本造的」——
断言是你**主动设计**的；守卫是**被一次事故推着**写出来的，条件会贴着**那一次**的形状。
两者共用同一句判据：**「它在另一个方向上会怎样？」**

**⚠️ 与准则 06 的分界**：06 问「这个判据在什么输入下为假」（针对**恒真**）；
本条问「**这个判据覆盖了这一类里的几种形状**」。
恒真的判据**从不说话**；单向守卫**会说话、会说对、然后在对的那一下之外永远沉默**。
