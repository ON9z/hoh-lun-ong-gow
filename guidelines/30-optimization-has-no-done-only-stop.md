# 优化类任务**没有「完成」**，只有「**停止**」—— 所以别给它写完成条件，给它写停止条件

判据：**优化 / 研究 / 改进类任务，禁止 `done_when`，只允许 `stop_when`。**
⚠ 而 `stop_when` 必须长成这两种形状之一：

```
stop_when: 固定窗口内，该类变更数 = 0
stop_when: 触发事件数 = 0
```

⛔ **「已完成 / 已最优 / 已收口」不算停止条件** —— 它们不可判定。
⚠ **没有 `stop_when` 的任务 = 未收口**（⚠ 哪怕它看起来做了很多事）。

---

## 为什么

⭐⭐ **「优化」「研究」「改进」这类任务【没有完成态】**：⭐ **每一次优化都会产生新的可优化点** ——
⚠ 这不是执行不力，是**这类任务的定义**使然。⇒ ⭐ **给它写 `done_when`，等于给它写了一个
永远为假的断言** ✓

⚠ 而**代价在一个具体的地方**：⭐ **我上一轮给使用者的答复是「一半达成」—— 而那本身就是一个错答**，
⚠ 因为它在**鼓励继续做**（「还差一半嘛」）⇒ ⭐ **一个不可判定的完成条件，会无限期地
为「继续投入」提供正当性** ✓

**实例（单人-单机长期自动化系统，2026-09-29）**：
⭐ 使用者**两次**问同一句话：「**机制完成没有？**」
⭐ 我第一次答了「**一半达成**」（⚠ 逐条列出：省了多少字节、哪些指标没改善）——
⚠ 而**他又问了一遍** ⇒ ⭐ **他要的不是进度，是「收工」** ✓

⚠ 那我为什么答不出「收工」？⭐ 因为我**默认「完成」是一件事**，而它**不是**：

| | 判据 |
|---|---|
| ⭐ **「完成」** | ⛔ **没有判据** —— ⭐ 直说没有（⚠ 别编一个，编出来的会被当成真的） |
| ⭐⭐ **「停止」** | ✅ **有判据**：**没有解冻事件 ⇒ 该类变更数 = 0** |

⭐⭐ **⇒ 停下来的形状**：把这件事从「**默认任务源**」改成「**解冻事件源**」——
⭐ **不是靠自觉，而是它不再出现在默认队列里** ✓
⚠ 且**只有三类解冻**（⚠ 满足其一才可动）：
**① 人明确指令 ② 可复现的任务阻塞 ③ 安全 / 数据一致性 / 错误落盘事故** ⇒ ⭐ **修完自动回冻** ✓

⚠⚠ **而「不构成解冻理由」同样重要**（⚠ 否则它会从后门回来）：
⭐ **「又发现 N 个可优化点」·「指标难看」·「还能更优雅」** ⇒ ⭐ **那只是【这件事是无穷的】** ✓

---

## 判据（写给下一个人）

⭐ 接到「优化 X」这类任务时，先写 `stop_when`（⚠ 在动手之前）：
- ⚠ 写不出 ⇒ ⭐ **这个任务没有终点，你会一直做下去**（⚠ 而每一步看起来都在产出真东西）
- ⭐ 写得出 ⇒ ⚠ **还要问一句：这个 `stop_when` 会被【它约束的那件事自己】满足吗？**
  （🌰 「再没有可优化点」—— ⚠ 那是被优化对象自己定义的，⛔ 永远为假）

⚠ **同族**：`#26`（机制自我服务率）—— ⭐ **#26 说的是「力气全花在机制上了」，
本条说的是「怎么把它停下来」** ✓
