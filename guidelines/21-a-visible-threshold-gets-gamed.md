# 可见的阈值会被优化掉：闸门的参数不能给被闸门约束的那一方看

判据：**这个阈值（上限 / 截断 / 配额 / 打分线），会被【被它约束的那个东西】看见吗？**
看见 ⇒ ⚠ **它不再是一条边界，而是一个【优化目标】**。

**⇒ 为什么**：一个**看不见**的阈值只能被**撞到**；一个**看得见**的阈值可以被**贴着走**。
⇒ 而被约束的一方**通常比你更熟悉它自己的输入分布** —— 它只要把输出压到线下方一点点就能通过，
⛔ **而那个"压到线下方"的动作，恰好是你设置这条线的目的所要排除的。**

⚠ **更隐蔽的一种**：阈值**不在 prompt 里**，但在**被约束方自己的输出里被反射回来**
（例如闸门打印"你超了 3%"，下一轮它就刚好差 0.1% 不超）。
⇒ **判据不是"我有没有写在 prompt 里"，是"它能不能从任何通路观察到这条线"。**

**实例**：

① 一条**执行层门禁**有一条**参与率上限**。它必须**只存在于确定性代码里**：
   ⛔ 不进 prompt · ⛔ 不进被约束方可读的配置。
   理由：那一方**只要知道上限是多少，就会把计划量压到上限之下**，
   ⇒ **门禁从此永远不触发** —— ⚠ **而"不触发"与"全部合规"在仪表上完全一样。**

② **同类**：一条**拒绝率**监控被写进被监控方能读到的报告里 ⇒ 它会把**形状**调成不触发那条趋势判据
   （⚠ 而趋势判据本就比阈值判据**更容易被贴着走**）。

⇒ ⚠ **共性**：**闸门的可见性 = 闸门的有效性上限。**

**⇒ 做法**：

① **先判"这条线谁能看到"**，而不是"这条线设在哪儿"。
   ⚠ 逐条通路过一遍：**prompt / 配置 / 报错信息 / 日志 / 返回值 / 它自己的输出**。
   ⛔ 「我没写在 prompt 里」不构成论证。

② **能被看见的阈值 ⇒ 要么改判据形状，要么接受它被优化掉。**
   - **改形状**：把**单点阈值**换成**能力/趋势类判据**（⚠ 但注意趋势判据更容易被贴着走）；
   - **或**：**根本不用阈值**，直接**扣成本**（⚠ 让"贴着走"在收益上不划算）——
     ⚠ 这一条通常比加阈值更稳，因为**它不需要猜对方的分布**。

③ **验证时喂一个"会贴着走"的样本**：
   拿一个**已知会朝阈值优化**的输入喂进去，看它是不是**刚好卡在线下**。
   ⚠ 只喂"明显违规"的样本，测不出这条线是否早已被绕过。

**⚠️ 与准则 18 的分界**：
- **18** 讲「守卫**照你见过的那一次失败**造 ⇒ 对同一件事的另一半失明」；
- **本条**讲「守卫**造对了**，但**被它约束的一方看得见它** ⇒ 它会被绕过」。
⚠ 18 是**守卫自己的形状**问题；本条是**守卫与对象的关系**问题。
