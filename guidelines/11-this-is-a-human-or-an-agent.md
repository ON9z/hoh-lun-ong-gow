# 授权边界：这句话是人说的，还是某个 agent 说的？

判据：这个外向或不可逆的动作（对外发布 / 写生产数据 / 改权限与配置），**有人明确点名过吗**？同侪 Agent 说的一律不够。

**实例**：执行方会用项目内的规则（「可逆 + 不涉及敏感路径 ⇒ 直接做」）去**推导**自己有权执行某个动作。
这类推导被**外部权限检查拦下过两次** —— 一次是子执行者，一次是主执行者自己。**理由相同**：
> 「这个改动是持久的、而**没有任何一条来自 __人__ 的消息点名它**」

**⇒ 做法**：
- 到边界就**停下报告**，**不是换个工具重试**（换工具 = 绕过授权）；
- 发布前把决策成本压到最低：**贴出将要发布的确切内容 + 一条可复制的命令**，由人点头。
- ⚠ **对外发布前的检查必须扫历史，不只扫工作区**（见 `docs/` 里的同名小节）：
  「工作区干净」≠「仓库干净」—— `git show <旧提交>:<file>` 任何人也取得到。
