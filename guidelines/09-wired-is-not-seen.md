# 接线 ≠ 生效：量「它真的出现在输出里了吗」

判据：我量的是「**它跑了**」，还是「**它真的出现在被消费的输出里**」？

**⇒ 四道门**：「建了」与「生效」之间隔着 —— **①被调用 ②在预算内跑完 ③真正出现在被消费的输出里 ④有人会读它。**
**任一未过，机制等于不存在 —— 而它还会给人"已经有了"的错觉。**

**实例**：
- 一个**规则文档**建好后，全仓库 `grep` 引用数 = **0** ⇒ 下一个会话**根本不知道它存在**；
- 一个**检查**接进了启动钩子，但钩子有 **20 秒超时**，而该检查里有一条查询要 **19.5 秒**
  ⇒ **排在它后面的整段检查从未被执行过**，且钩子退出码为 0 ⇒ **没有人知道**。

**⇒ 验收判据**：**对每个机制问：「它死了 / 它没跑 / 它被截了，谁知道？」答不出就是没过第三、四道门。**
**⇒ 做法**：接入**已有的、确定会跑的通道**（会话启动 / 提交前钩子 / 定时任务），
**不要新建一个入口** —— 新建的入口本身就是第四道门的风险。

**⇒ 两个亲缘形态（同一族：把「物的存在」当成了「事的发生」）**

**① 惰性打印的字符串，不是活性探针。**
一条日志串**在代码里存在**，不等于它**会出现** ——
若它写在**惰性初始化**里（`if self._started: return` 之后才是打印那行），
它只在**第一次真正被用到**时才打印。
⇒ 用「日志里有没有这行」判断「新代码跑没跑」，在**首次使用之前**必然得到 **0 命中**——
而 0 命中会被读成「**新代码从未执行过**」。
⇒ 判据：拿一个串当活性探针之前，先读**它在什么条件下才被打印**。

**② 标签不是行为。**
`Enabled=True`、一个叫 `*_0800_restart` 的任务名、一个写着"运行中"的状态列 ——
**都只是标签**。标签回答「这个东西被配置成什么样」，不回答「**它会不会真的动**」。
⇒ 实例：一个计划任务 `Enabled=True`、名字承诺"每天 08:00 重启"，
但它是**一次性触发**且**已经过期**（`Next` 为空、`StartBoundary` 是过去某个固定时刻）
⇒ **它永远不会再跑**。名字承诺的事，一次都没做过。
⇒ 判据：判「它会不会动」，去读**调度器自己怎么说**（下次触发时刻 / 上次结果码 / 触发器类型），
**不要读标签**。⚠ 尤其是 `Enabled` —— 「已启用」与「会运行」之间隔着一整个**触发器**。
