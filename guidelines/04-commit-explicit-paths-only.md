# 只提交指定路径：`add` 之后不带路径提交会卷走别人的暂存

判据：提交前，我核对过**暂存区的文件名与数量**吗？

**实例**：一天内**4 次** —— A `git add` 自己的文件后执行**不带路径**的提交，
把 B **已暂存但尚未提交**的文件一并提交。内容不丢，但**归属错**（提交信息不描述被卷进来的文件），
并打乱并发协作者的状态。

**⇒ 做法**：用「只提交指定路径」的形式；或提交前打印暂存区清单并**数一遍**。
**⇒ 并发环境额外要求**：给每个执行者**显式设置提交身份** —— 否则事后**无法从作者信息判断归属**，
主执行者的「无缺陷确认」会因此失效。

**⚠️ 一个**不同的**形态 —— 本条防不住它（机制不同，**别把计数并进来**）**

我 `git add` 的是**明确点名的路径**，自认为完全符合本条。
**但 `git add <路径>` 拿的是整个文件，不是「我的那几个 hunk」。**
当时另一名执行者正在**同一个文件**里做它自己的修复 ⇒ **它的改动被我一并提交了，
而我的提交信息里一个字都没提。**

> **⇒ 路径级粒度 ≠ 块级粒度。** 本条解决的是「扫到别的路径」，
> **没解决「同一文件里别人的块」** —— 而两者**症状相同**（提交信息不描述被卷进来的内容），
> 所以只自查「我是不是点名了」**永远查不出后者**。

**⇒ 做法（提交前跑，三步）**：
1. `git status --porcelain` —— **此刻**谁在写（不是几分钟前）
2. `git diff --stat <我点名的路径>` —— 那些改动**是不是我的**
3. 共享热文件且他人同时在改 ⇒ **按 hunk 暂存**，或**等对方落库**

⚠ **附带一条**：`git status` 也会读到**过期状态**。
我曾据一份"队友的修复还没提交"的读数去行动，而它**已经提交了**（在**我的**提交里）。
**⇒ 读数要绑时刻；动作前重读。**
