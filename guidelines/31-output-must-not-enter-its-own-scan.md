# 输出物不得写进**它自己的输入 / 扫描 / 统计 / 提交范围**

判据：**运行前检查一次 ——**

```
input_roots ∩ output_roots = ∅ ?
```

⚠ **非空 ⇒ 拒绝运行**（⚠ 不是「跑完再看」，是**跑之前就拒**）。
⭐ 若**必须写进扫描范围**（🌰 备份、日志、缓存、生成物与来源同目录）⇒
**必须在【同一处】把这个输出从扫描 / 统计 / 提交规则里【显式排除】，并标注排除项** ✓

⭐ 一句话：**排除规则与输出路径要【同生共死】** ——
⚠ 只加输出、不加排除 ⇒ ⛔ 下一轮它就会被当成输入 ✓

---

## 为什么

⭐⭐ **落在扫描范围内的输出物，会被这个工具【自己】当成输入。**
⚠ 而它**看起来和真输入完全一样** ⇒ ⚠ 你得到的数字**每次跑都不一样**，
且**跑一次涨一次**，⛔ 而**没有任何检查会红**（⚠ 因为对那个工具来说，那些就是合法的输入）✓

⭐ 而它常常是**为了好习惯而引入的**：⭐ 「**改前先备份**」是一个好习惯，
⚠ 而**备份落到哪儿**决定了它是好习惯还是污染源 ✓

**实例（单人-单机长期自动化系统，2026-09-29）**：
⭐ 一个长期自动化系统的 Agent 每次改一个「准则/记忆」文件前都**先备份**。
⚠ 它把备份写在了**被那个工具扫描的同一个目录**里。
⚠ 而备份的**扩展名恰好满足**扫描规则 ⇒ ⭐ **备份被算进了统计数** ✓

⚠ 而它**为什么会藏这么久**？⭐ 因为**大多数人以为的两道屏都不成立**：
- ⛔ 「以 `.` 开头 ⇒ 通配不匹配」 ⚠ **错**（实测：命中，差 **0**）
- ⛔ 「扩展名不同 ⇒ 不被扫」 ⚠ **只对一半成立**（⚠ 备份有两种命名，一种**恰好**以被扫的扩展名结尾）

⭐⭐ **⇒ 正确结论**：⭐ **那道屏是【猜的】，不是【设计出来的】**
⇒ ⚠ 它挡住的不是这一类，只是**恰好路过的那一个形状** ✓

⚠ 而**真正的危害不是统计数字**：⭐ 扫描结果会进入**注入 / 索引 / 决策**，
⇒ ⭐ **几十份「旧版本」会被当成【独立的新内容】** —— 而它们**读起来完全像真的** ✓

## 判据（写给下一个人）

⭐ 加任何「**生成 / 备份 / 缓存 / 日志**」动作之前，先答两句：
1. **它写进哪个根？**
2. **有哪些东西会扫那个根？**（⚠ 包括：索引脚本、注入钩子、统计、清理、提交规则）

⚠ 答不出第 2 句 ⇒ ⭐ **那个根就是它的扫描范围**，⛔ 别写进去 ✓
⭐ 若一定要写进去 ⇒ **同一处加排除**，⚠ 且**排除要能被复跑验证**（🌰 一条断言：该根下**不存在**这类名字）✓

⚠ **同族**：`#13`（准入 ≠ 清理：只做准入、没有回收的守卫会单调累积）——
⭐ **#13 说的是「进了就出不去」，本条说的是「它根本不该进」** ✓
